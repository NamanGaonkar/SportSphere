🔧 Root causes found & fixed

1.  ClientException  /  SocketException  on phone — the release  AndroidManifest.xml  had no INTERNET permission (debug builds get it merged automatically; release builds don't). The app literally couldn't open sockets. Fixed, and verified inside the built APK:

uses-permission: name='android.permission.INTERNET' ✅

New APK (17.5MB) rebuilt and reinstalled on your phone — sign in with  athlete@sportsphere.app  /  Passw0rd! .

2. Logins failing even on web — the demo users I'd seeded directly into  auth.users  were rejected by Supabase's hosted auth server. I deleted them and recreated all 8 via the official admin API ( scripts/create_demo_users.py ), then re-linked all demo data. Verified via the exact REST endpoint the apps use:

athlete@ → LOGIN OK   coach@ → LOGIN OK   admin@ → LOGIN OK
SIGNUP OK (session returned immediately)

3. Password visibility + sign-up — added the 👁 toggle on both apps, plus full sign-up (name + role) on web and mobile. Also enabled  mailer_autoconfirm  so sign-ups work instantly with no email verification.
